岛屿数量，一步一步看

先看提示，卡住时再往下翻一层。下面的海图可以逐步播放：看清楚「什么时候 +1」和「为什么同一座岛不会被数两次」，这道题就会了。

分层提示

提示 1换个说法看题目点开

「数岛屿」其实就是「数有几块互相连通的陆地」。

想象你从左上角开始，一格一格往右、往下扫。什么时候答案应该 +1？

提示 2怎么避免重复计数点开

扫到一块还没被数过的陆地，答案就 +1。

难点在后面：同一座岛有很多格子，之后还会扫到它们。所以 +1 之后，要立刻把这座岛的所有格子都做上记号（比如直接改成 '0'，相当于把岛「淹掉」），以后扫到就直接跳过。

提示 3怎么找出整座岛点开

从刚发现的格子出发，往上、下、左、右四个方向扩散：遇到陆地就做记号并继续扩散，遇到水或者走出边界就停。

这就是 DFS（递归或用栈）或 BFS（用队列），两种都能过。下面的动画用的是栈。

最后伪代码骨架（想自己写就先别看）点开 
count = 0
for 每个格子 (i, j):
    if grid[i][j] == '1':
        count += 1
        sink(i, j)          // 把这整座岛淹掉

sink(i, j):
    if (i, j) 越界 或 grid[i][j] != '1':
        return
    grid[i][j] = '0'        // 做记号
    sink(i-1, j); sink(i+1, j)
    sink(i, j-1); sink(i, j+1)

return count

写代码时注意

先判断再递归

进 sink 第一件事就是判断越界和是不是陆地，四个方向就不用各写一遍判断。

先做记号再扩散

记号要在扩散之前做，否则两个相邻格子会互相跳来跳去，死循环。

格子是字符

Java 里 grid 是 char[][]，比较要写 '1'，不是数字 1。

复杂度

每个格子最多被访问常数次，时间 O(m·n)；最坏情况下递归深度也是 O(m·n)。

第 K 个最大元素，快速选择怎么只排一半

标准解法是快速选择：借用快速排序的划分，每一轮把数组分成「比 pivot 小 / 等于 / 比 pivot 大」三段，然后只往答案所在的那一段继续找。下面可以逐步播放每一次比较和交换。

分层提示

提示 1换成下标来想点开

第 k 大的元素，就是把数组升序排好后下标为 n - k 的那个数。

我们只关心这一个位置放的是谁，其他位置排没排好都无所谓。

提示 2借快速排序的一步点开

快速排序的划分（partition）做完一趟后，pivot 会落在它排好序后的最终位置，左边都比它小，右边都比它大。

比较这个位置和目标下标 n - k：相等就找到了；目标在左边就只处理左边，在右边就只处理右边。另一半直接扔掉，不用再排。

提示 3为什么是 O(n)，以及两个坑点开

每轮平均扔掉一半，总工作量大约是 n + n/2 + n/4 + … ≈ 2n，所以平均 O(n)。

坑 1：pivot 固定取第一个元素，遇到有序数组每轮只扔掉一个，退化成 O(n²)。所以 pivot 要随机选。

坑 2：力扣有一个全是相同元素的大用例，普通两段划分也会退化。用三路划分把等于 pivot 的数单独放中间，一轮就结束。

代码标准解法：随机 pivot + 三路划分点开 
import random

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        target = len(nums) - k          # 第 k 大 = 升序下标 n-k
        lo, hi = 0, len(nums) - 1
        while True:
            pivot = nums[random.randint(lo, hi)]
            lt, i, gt = lo, lo, hi      # [lo,lt) 小于  [lt,i) 等于  (gt,hi] 大于
            while i <= gt:
                if nums[i] < pivot:
                    nums[lt], nums[i] = nums[i], nums[lt]
                    lt += 1
                    i += 1
                elif nums[i] > pivot:
                    nums[i], nums[gt] = nums[gt], nums[i]
                    gt -= 1             # 换过来的数还没看过，i 不动
                else:
                    i += 1
            if target < lt:
                hi = lt - 1             # 答案在小于区
            elif target > gt:
                lo = gt + 1             # 答案在大于区
            else:
                return pivot            # 落在等于区，就是 pivot
代码另一种常考写法：大小为 k 的小顶堆点开

堆里始终保留目前见过的最大的 k 个数，堆顶是其中最小的，也就是第 k 大。复杂度 O(n log k)，不满足题目的 O(n)，但写起来短、不改原数组，面试时也经常被追问。

import heapq

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        heap = nums[:k]
        heapq.heapify(heap)             # 先放前 k 个，建小顶堆
        for x in nums[k:]:
            if x > heap[0]:             # 比堆顶大，才有资格进前 k
                heapq.heapreplace(heap, x)
        return heap[0]

三种做法对比

做法时间额外空间说明
直接排序O(n log n)O(1)～O(n)一行就能写完，但不满足题目要求
小顶堆O(n log k)O(k)不改原数组，适合数据流、数据量大到放不进内存的场景

写代码时注意

和 gt 交换后 i 不动

从右边换过来的数还没比较过，下一轮要接着看 nums[i]。和 lt 交换的数已经看过，所以 i 可以前进。

循环条件是 i ≤ gt

gt 指向的那个数也还没看过，写成 i < gt 会漏掉一个。

用迭代不用递归

每轮只进一边，用 while True 改 lo、hi 就够了，不需要递归，也就没有递归深度的问题。

第 k 大不是第 k 小

升序下标是 n - k，不是 k - 1。示例 2 的 […,5,5,6] 里第 2 大是 5，重复的数要算两次。
